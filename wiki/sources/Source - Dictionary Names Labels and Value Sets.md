# Source — Dictionary Names, Labels, and Value Sets

Excel workbook exporting the **[[1_Projects/ASPSI-DOH-CAPI-CSPro-Development/wiki/concepts/CSPro Data Dictionary|CSPro data dictionary]]** — item names, human-readable labels (multi-language), and coded value sets — for **all three CSPro instruments at once**: F1 (Facility Head), F3 (Patient), and F4 (Household). This is the authoritative name→label→code reference. It is a **machine export of the `.dcf` dictionaries** (which are themselves generated by each instrument's `generate_dcf.py`), not a hand-authored draft.

> [!important] Point-in-time snapshot — regenerate on every new instrument version
> This workbook is the version **as of 2026-07-20**, matching the instruments' current build. It is **not evergreen**: the counts, labels, and value sets below are true only for that build. The export is produced by running the **Dictionary Macros** against the current `.dcf` files — **re-extract via Dictionary Macros whenever a new version of the instruments ships**, drop the refreshed workbook into `raw/`, and re-ingest (the numbers here will move). Treat any figure on this page as pinned to the 2026-07-20 build unless the page has been re-ingested since.

It supersedes and greatly extends the April-9 single-instrument draft [[Source - Facility Head Data Dictionary and Value Sets]] (that one was an early flat-record F1 sample of ~115 items; F1 here is now 12 records / 316 items).

> [!note] F2 is absent by design
> F2 (Healthcare Worker) is a **PWA**, not a CSPro instrument, so it has no `.dcf` and does not appear here. Its field/label/option definitions live in the F2 app schema (`app/src/generated/items.ts`), separate from this workbook. (See [[F2 Admin Portal]].)

## Workbook layout

Six sheets — a **Names & Labels** sheet and a **Value Sets** sheet per instrument. Columns are indent-coded to show the CSPro tree (**Level → Record → Item**), and the label is repeated across one column **per dictionary language** (English is the first/primary column).

| Instrument | Level | Records | Items | Value sets | Value rows | Language columns |
|---|---|---|---|---|---|---|
| **F1** Facility Head (`FACILITYHEADSURVEY_LEVEL`) | 1 | 12 | 316 | 151 | 871 | ~7 |
| **F3** Patient (`PATIENTSURVEY_LEVEL`) | 1 | 38 | 370 | 207 | 1,104 | ~6 |
| **F4** Household (`HOUSEHOLDSURVEY_LEVEL`) | 1 | 34 | 299 | 168 | 810 | ~6 |

Each instrument is a **single CSPro level** with an ID-items record (`_IDS0`, holding `QUESTIONNAIRE_NUMBER` — the 12-digit key) plus a `FIELD_CONTROL` record and one record per questionnaire section; rosters/matrices are their own repeating records.

## Record structure (section map)

The record names track the questionnaire sections directly — a clean audit surface for "does the build match the instrument."

- **F1 (A–H):** `FIELD_CONTROL`, `HEALTH_FACILITY_AND_GEOGRAPHIC_IDENTIFICATION`, `REC_FACILITY_CAPTURE`, `A_FACILITY_HEAD_PROFILE`, `B_FACILITY_PROFILE`, `C_UHC_IMPLEMENTATION`, `D_YAKAP_KONSULTA`, `E_BUCAS_GAMOT`, `F_DOH_LICENSING`, `G_SERVICE_DELIVERY`, `H_HUMAN_RESOURCES`.
- **F3 (A–L):** consent, patient profile, UHC awareness, PhilHealth registration, primary/outpatient/inpatient care, financial risk, satisfaction, access to medicines, referrals — plus **many payment/lab rosters** (`Q92_PAY_ROSTER`, `Q94_LAB_ROSTER`, `Q96_PAY_ROSTER`, `Q98_PAY_ROSTER`, `Q107/109/112/113_PAY_ROSTER`, …) that split the billed/paid line-items out of the main care records. `REC_FACILITY_CAPTURE` / `REC_PATIENT_HOME_CAPTURE` / `REC_CASE_VERIFICATION` carry the disposition-photo/verification capture.
- **F4 (A–Q):** consent, respondent profile, **household roster** (`C_HOUSEHOLD_ROSTER`) + private-insurance gate/roster, UHC/YAKAP/BUCAS awareness, access to medicines, PhilHealth, primary care, health-seeking, referrals, NBB/ZBB/MAIFIP, and a large **Section-N expenditure block** built as a stack of rosters (`N_FOOD_ROSTER`, `N_HOUSEHOLD_EXPENDITURES`, `N_WKOTH_ROSTER`, `N_NF1M/6M/12M_ROSTER`, `N_H1M/6M/12M_ROSTER` + `_TOTAL` records), then sources of funds, financial risk, financial anxiety.

## Labels — multi-language

Each name carries a stack of label columns, one per CSPro dictionary language (F1 ~7, F3/F4 ~6), English first. Translated instruments (F3, F4) show real regional text in the secondary columns — e.g. Tagalog *"Pangalan ng Survey Team Leader"* and Waray *"Ngaran han Survey Team Leader"* for `SURVEY_TEAM_LEADER_S_NAME`; where a slot still mirrors the English string, that language's translation for that item is pending/unwired. This is the dictionary side of the [[CAPI Seven-Language Translation Build]] / [[CSPro Multi-Language Applications]] work (see [[Source - Survey Tool Translations Delivery (Aidan 2026-06-02)]]).

## Value sets — highlights

Value sets define the coded response options (label per language + a numeric code). Two things worth flagging:

**1. Result-of-Visit / disposition codes differ across instruments** — corroborating the disposition-harmonization item DOH raised (see [[Analysis - XJ PAPI-vs-CAPI Reviews vs Current CAPI Build]]) and the replacement/break-off design:

| | Result of First Visit codes |
|---|---|
| **F1** | Completed 1 · Postponed 2 · Refused 3 · Incomplete 4 · Replaced 5 |
| **F3** | Completed 1 · Completed at the Hospital 2 · Postponed 3 · Incomplete 4 · Completed at Home 5 · **Withdraw Participation/Consent** 6 · Replaced 7 |
| **F4** | Completed 1 · Postponed 2 · Incomplete 3 · **Withdraw Participation/Consent** 4 · Replaced 5 |

F3/F4 use **"Withdraw Participation/Consent"** in place of F1's **"Refused"** (the April change XJ asked ASPSI to justify), and `Replaced` is the disposition that drives the BREAKOFF-based replacement flow. This is deliberate, not an inconsistency — but it is the concrete data behind the "harmonize the codes/order across forms" comment.

**2. "Not Applicable" / DK coding follows the project convention, not DHS.** Explicit "Not applicable" is the highest code at the field width (9 / 99 / 999); "Don't know" is coded per-question rather than a global sentinel; skipped fields are blank (`notappl`), never a value-set entry. The rule and rationale are in [[F-Series Value Set Conventions]].

## Why this source matters

- **Authoritative codebook** for the three CSPro instruments — the same name/label/value-set data that drives the labeled SPSS (`.sav`) exports and the CSWeb reporting layer. Analysts can read it without opening CSPro Designer.
- **Audit surface** for the DOH/XJ review: section records and value sets here are what "confirm the skip/validation is programmed" and "other-specify field present" questions get checked against (the C-bucket "supply a matrix" answer).
- **Snapshot, not source of truth for codes** — the generators (`generate_dcf.py` + `cspro_helpers.py`) remain the source of truth; any code change is made there and regenerated, never hand-edited (see [[CSPro Data Dictionary]]).
