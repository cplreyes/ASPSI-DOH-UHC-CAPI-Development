How we build CAPI

The same system every engagement gets: instrument, field hub, monitoring, and documented, analysis-ready data.

The pipeline

Paper questionnaire in, documented data set out.

StageWhat happens
InstrumentThe approved paper questionnaire becomes a tablet application — skip logic, range and consistency checks, and multi-language question text — generated from scripts, so a change is re-generated rather than hand-edited.
FieldEnumerators work offline on CSEntry; supervisors assign and collect cases, over Bluetooth where there is no signal, and relay them to the server.
SyncA central CSWeb hub receives cases, keeps every revision, and breaks them out into relational tables for reporting.
MonitorDashboards and maps rebuild every two minutes: coverage against plan, productivity, and data-quality alerts while the team is still in the field.
DeliverExports in CSV, SPSS, Stata and R with labels embedded, plus a codebook documented to the DDI standard used by the PSA Data Archive.

Standards we work to

Documentation

DDI-Codebook 2.5 elements for every variable — label, question, universe, categories, missing codes — so a data set can be deposited in a national archive without being re-documented.

Data quality

Validation at the point of entry, not at encoding: hard blocks for impossible values, soft warnings for implausible ones, and GPS plus verification photos to confirm the visit happened.

Reproducibility

Instruments, exports and documentation are generated by scripts under version control. Any build can be regenerated exactly, and every deployed version is stamped on the device.
