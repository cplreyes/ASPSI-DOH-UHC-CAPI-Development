## Root cause

`F1/translations/ceb.json` carried `sa primary care facilities>` on **24** `…_VS1:9` keys — a June-5-era dangling tail
(the tail of a neighbouring sentence, cut at a `>`). Only two of those keys have a code 9 in the dictionary
(`Q10_1_UHC_ATTRIB_VS1`, the one probe built from `UHC_ATTRIB_NA`, and `Q12_2_PHU_ROLE_VS1`); the other 22 were
stale keys with no dcf anchor. The Aug-21 wave could not repair Q10.1 because its `keep: null` override (the paper
prints code 8's text on code 9) only *blocks writes* — it does not delete what was already there — and Q12.2's key
was never in the extract at all.

Fix: 24 locale-scoped `"remove": true` entries in `data/translations-official/aug21-overrides.json` (F1 block; the
Q10.1 entry flips from `keep: null` to `remove`) → `apply_aug21.py --only F1 --extract <task-48 check>
--fail-on-pre --apply` removed 5 + 19 keys, strict replay 0/0/0, duplicate-label gate clean. `.dcf` diff vs 4.1.2 =
exactly the two labels; `grep` for the fragment in the dcf and the map = 0.

Why the tester saw it as "the last option should be *Implemented as a direct result…*": on the paper, Q10.1's options
run 1 → 9 and the fragment sat on the last row; the tester matched the CAPI's last row to the paper's *first* row.
The option ORDER in CAPI matches the paper; only the code-9 label was wrong.
